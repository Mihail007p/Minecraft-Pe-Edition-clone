# Постоянные инструкции для ИИ-агентов

Эти правила действуют для всего репозитория.

## Ссылка на игру — в каждом итоговом ответе

По просьбе владельца проекта всегда включайте в итоговый ответ пользователю
кликабельную ссылку на игру — не ограничивайтесь словами «предпросмотр запущен».
Правило действует и для ответов без изменений кода. Отвечайте по-русски, если
пользователь не попросил другой язык.

- Постоянная ссылка опубликованной игры:
  [Открыть игру](https://mihail007p.github.io/Minecraft-Pe-Edition-clone/).
- Если изменения ещё не опубликованы, явно сообщите, что постоянная ссылка
  может показывать предыдущую версию. Не утверждайте, что изменения доступны
  на опубликованном сайте, без подтверждения успешного развёртывания.
- Для проверки текущих изменений дополнительно давайте прямую ссылку на живой
  предпросмотр, если он запущен. В Arena её адрес имеет вид
  `https://{port}-{sandboxId}.e2b.app`; используйте только фактический порт
  работающего сервера и идентификатор текущей среды, не выдумывайте их.
- Ссылка на предпросмотр временная: не сохраняйте адрес конкретной среды
  как постоянный адрес игры. Не выдавайте `localhost` или `127.0.0.1`
  пользователю телефона в качестве доступной ссылки.
- Само требование дать ссылку не является разрешением на push, слияние PR
  или публикацию. Если предпросмотра нет, дайте постоянную ссылку и честно
  укажите статус текущих изменений.

## Обновление main после изменений и очистка веток Arena

По просьбе владельца проекта после каждого завершённого набора изменений
(включая документацию и эти инструкции) не оставляйте результат только
в рабочей ветке: проверяйте его и переносите в `main`. Это постоянное разрешение
на commit, push рабочей ветки, создание и слияние PR, а также безопасную очистку
старых веток Arena. Повторное подтверждение для этих действий не требуется,
если пользователь не попросил отложить публикацию или слияние.

1. Работайте в закреплённой за текущей сессией ветке. Не переключайтесь на `main`
   или другую ветку; отправляйте коммиты только в текущую рабочую ветку.
2. Перед отправкой проверяйте diff и запускайте `npm test`, `npm run build`
   и `git diff --check`. Не публикуйте секреты, зависимости и временные артефакты.
3. Создайте или обновите PR из рабочей ветки в `main`. Дождитесь успешных
   обязательных проверок. Слейте PR командой `gh pr merge <номер> --merge`
   (с явным номером, без `--auto`). Не обходите защиты веток и обязательное ревью.
   При ошибках тестов, конфликтах, проблемах доступа или других блокировках
   сначала устраните проблему либо честно сообщите пользователю, что `main`
   ещё не обновлён. Не используйте force-push в `main`.
4. После слияния проверьте статус публикации GitHub Pages для нового коммита
   в `main`. Сообщайте отдельно о слиянии и развёртывании: обновление ветки
   ещё не означает успешное обновление сайта.
5. Удаляйте старые удалённые и локальные ветки с префиксом `arena/` только после
   проверки, что их актуальные коммиты уже входят в `main` и нет открытого PR
   из этой ветки. Перед проверкой обновите сведения об удалённых ветках;
   недостаточно одного факта, что когда-то был слит PR: в ветке могли появиться
   новые коммиты. Не удаляйте ветки с неслитыми или непроверенными изменениями.
6. Никогда не удаляйте текущую ветку активной сессии, `main`, защищённые ветки
   и ветки без префикса `arena/`. Текущую ветку можно убрать в следующей сессии,
   когда она станет старой и будет проверена по предыдущему пункту.
7. В итоговом ответе кратко укажите статус `main`, публикации и очистки веток,
   а также дайте ссылку на игру по правилу выше. Не утверждайте успех без проверки.


### Очистка Arena обязательна при каждом завершении работы

Всегда выполняйте проверку старых веток `arena/*` после успешного слияния,
даже если изменились только инструкции. Удаляйте все проверенные слитые ветки,
а не только ветку последнего PR. Незавершённые изменения, открытый PR, защита
ветки или активная сессия — основание сохранить ветку и назвать причину в ответе.
Не включайте безусловное автоматическое удаление после merge: оно может удалить
ветку ещё активной сессии. Текущая ветка очищается следующей сессией по тем же
проверкам. Не удаляйте ветки только по возрасту или префиксу без проверки ancestry.
